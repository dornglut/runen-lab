# Runtime comparison — Runen Lab #9

Independent Rust research project comparing a restricted generated **Typed Differential Execution (TDE)** candidate against **Bevy ECS 0.20.1** and the pinned accepted **RunenECS** public API.

This is a downstream experiment, not framework implementation authority. No performance or general-purpose superiority claim follows from the correctness oracle.

## Correctness experiment

- All three implementations receive the same staged transactions from `src/contract.rs`.
- `src/bevy_backend.rs` uses Bevy App, relationships, change detection, scheduling, and publication.
- `src/runen_backend.rs` uses RunenECS World, typed directed relations, queries, scheduling, and publication.
- `src/tde.rs` uses project-local reverse-index and packet-cache maintenance partly generated by `tools/compile_rule.py`.
- `src/main.rs` compares authoritative source state, derived packets, SHA-256 digests, versions, changed/removed identities, rejection outcomes, and epochs with **28,022** deterministic independent reference cases in `fixtures/`.

The TDE generator recognizes **one fixed foreign-key join schema**; it does not compile arbitrary Rust code or provide a general differential runtime. The common staged admission path clones logical state and is intentionally excluded from any future backend timing.

## Reproduce

From this project directory, with the selected Rust toolchain and Python 3:

```sh
python3 tools/compile_rule.py --check
cargo fmt --all -- --check
cargo test --all-targets --locked
cargo clippy --all-targets --locked -- -D warnings
cargo run --release --locked
```

The repository-level `cargo validate` remains a separate required gate. A project-specific GitHub workflow runs this replay on the exact PR head; project validation integration is coordinated with Runen Lab draft PR #8 and must not overwrite that owner's independent work.

## Evidence and limitations

The fixtures were verified independently in Python; that is not Rust execution evidence. Real Rust correctness requires successful exact-head project tests and replay. Benchmarks are **not implemented** in this candidate. Any future comparison must time equivalent operations on one host, include update propagation and publications, report memory and user-authored coordination, preserve native ECS capabilities, and retain raw measurements. This project must not be used as proof that TDE outperforms Bevy or RunenECS.
